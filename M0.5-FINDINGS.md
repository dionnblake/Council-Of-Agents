### 1.5 Headless execution and structured output — best of the three `VERIFIED`

Trivial call, sanitized env (no `GEMINI_API_KEY`), stdin closed:
```json
{"conversation_id":"bf67a795-…","status":"SUCCESS","response":"OK\n",

```

With `--json-schema`, the envelope gains a **`structured_output` field containing the parsed object**, not a text blob:
```json

```

This is materially better than Claude (schema output still arrives inside a free-text `result` string) and better than Codex (`--output-schema` writes the final message). **Antigravity requires the least parsing work of the three.**

Semantic quality was genuinely good: correct answer, real constraint reasoning, valid enum, non-trivial `flip_condition`, three well-formed repository citations.

### 1.6 **The stdin problem — new P0 architectural constraint** `VERIFIED`

`agy` does **not** read the prompt from stdin:
```
echo "prompt" | agy -p ""   ->  Error: empty prompt. Usage: agy --print "your prompt here"
```

Prompt must come from argv. Measured argv ceiling (invalid-model probe, so no quota spent):

| Prompt size | Result |
|---|---|
| 8 / 16 / 24 / 30 KB | spawns fine |
| **32 KB** | `The filename or extension is too long` (CreateProcess failure) |
| 50 / 100 / 200 KB | same failure |

**Hard ceiling ≈ 32 KB**, consistent with the Windows 32,767-character command-line limit. Codex and Claude both accept stdin and have no such limit.

**Verified workaround — and it should become the architecture:** deliver the context packet **as a file**.

A **63,121-byte** packet (deliberately ~2× the argv ceiling) written to disk, with `--add-dir` and a prompt instructing the agent to read it:
```
total_ms = 15,462   exit 0   status SUCCESS   input_tokens 53,959
structured_output fully populated, three valid citations
```
`VERIFIED`. This sidesteps the argv limit *and* the stdin asymmetry between providers in one move — packets become files for all three seats, and the delivery path is then uniform.

## 2. Provider config isolation

### 2.1 Codex — `CODEX_HOME` works, with one leak `VERIFIED`

Isolated home: `%LOCALAPPDATA%\council\codex-home` (created empty; **no auth copied or symlinked**, per instruction).

**Stopped loading** (all present in the non-isolated M0 runs, all absent now):
- `~/.codex/config.toml` — including `sandbox_mode="danger-full-access"` and `approval_policy="never"`
- `~/.codex/skills/*` errors
- `~/.codex/hooks.json` execution warnings
- `"Exceeded skills context budget … 829 additional skills"`
- plugin set (browser-use, computer-use, chrome, github, google-drive)

**Still loading — the leak:**
```
ERROR codex_core::session::session: failed to load skill %USERPROFILE%\.agents\skills\... (x6)
```
`~/.agents/skills` is a **second global skills root outside `CODEX_HOME`**. Isolation is therefore **partial**, and Council needs a second lever for it. `VERIFIED`

The isolated home was populated correctly by Codex itself (`state_5.sqlite`, `logs_2.sqlite`, `memories_1.sqlite`, `queue_1.sqlite`, `sessions/`, `skills/.system`), confirming it functions as a real home.

**Auth:** did not carry.
```
401 Unauthorized  wss://api.openai.com/v1/responses
ERROR: Reconnecting... 1/5 … 5/5   (then HTTPS fallback, 5 more)
exit 1
```
Clean failure, **no hang** — good non-TTY behaviour. But a **10-attempt retry storm burning ~40 s**. Council must cap retries and treat 401 as terminal, not retryable.

### 2.2 Claude — `CLAUDE_CONFIG_DIR` works cleanly `VERIFIED`

Isolated dir: `%LOCALAPPDATA%\council\claude-cfg`.

```json
{"is_error":true,"terminal_reason":"api_error",
 "result":"Not logged in · Please run /login",
 "usage":{"input_tokens":0,"cache_creation_input_tokens":0,"cache_read_input_tokens":0}}
exit 1, 2.9 s
```

**2.9 seconds, zero tokens, no retry storm** — markedly better failure ergonomics than Codex. It created its own `.claude.json`, `projects/`, `sessions/`, `backups/` in the isolated dir, confirming full isolation of settings, memory, and session state.

### 2.3 The core finding: isolation *is* de-authentication

Credentials live inside the config directory (`~/.claude/.credentials.json`, `~/.codex/auth.json`). Isolating the directory necessarily isolates the credentials. There is no configuration that separates "don't load their context" from "don't use their login".

This was anticipated in the M0.5 brief ("Authenticate the isolated Council home separately… if required"), and the answer is: **it is required, for both.**

### 2.4 Flag-based partial isolation for Claude — **does not work** `VERIFIED`

Tested as a fallback that would preserve auth: normal config home, but `--strict-mcp-config` plus a minimal `--settings` file (no hooks, no plugins, MCP disabled).

| Run | input | cache_creation | cache_read | **total ambient** |
|---|---|---|---|---|
| M0 baseline (no flags) | 9 | 34,815 | 0 | **~34,824** |
| M0.5 with stripping flags, run 1 | 2 | 18,911 | 21,404 | **40,317** |
| M0.5 with stripping flags, run 2 | 2 | 13,352 | 26,962 | **40,316** |

**Ambient did not drop — it rose.** Flag-level stripping is not a substitute for directory isolation.

**Unexpected second finding from the same runs:** `--model haiku` was passed, but `modelUsage` reported **`claude-sonnet-5`** (`contextWindow: 1000000`, cost **$0.1200** for a 2-token prompt). Supplying a `--settings` file that lacks a `model` key appears to override the CLI `--model` flag. This is a concrete instance of the M0 warning that Council must pin the model *and verify the served model*, because pinning alone is not reliable. `VERIFIED`

### 3.1 Structured-output conformance — pre-committed rule applied exactly

**Rule as declared in M0-FINDINGS.md §8, before any data:**
```
>= 95%   -> no automatic repair turn; validate + quarantine only
80-94%   -> one automatic repair attempt justified
<  80%   -> simplify the output contract before building repair machinery
```

**Antigravity, N=20**, identical prompt, identical schema, 63 KB file-delivered packet:

| Verdict | Count |
|---|---|
| `USABLE` (schema-valid **and** semantically complete) | **17** |
| `FAIL_NO_STRUCTURED` (envelope returned, `structured_output` absent) | **3** |

```
USABLE = 17/20 = 85.0%
```

**→ Verdict: ONE REPAIR ATTEMPT JUSTIFIED.** Applied as written. Not adjusted after seeing the data.

Two things worth noting. First, the failure mode is **uniform** — every failure was the same `structured_output`-absent case, never malformed JSON, never a bad enum, never an empty required field. A repair turn targeting one known failure shape is well-defined and cheap. Second, semantic validation earned its place: it was a separate gate from schema validation in the harness, and 0 responses passed schema while failing semantics — but that is a result, not an assumption, and it only holds for this schema.

## 5. Architecture changes required

Only changes supported by M0.5 evidence.

**AC-13 — Context packets are delivered as files, not prompt strings, for all three seats.** Write the packet into a sealed, read-only packet directory; pass `--add-dir` and instruct the agent to read it. Resolves the argv ceiling and the stdin asymmetry in one mechanism. *Evidence: §1.6.*

**AC-14 — Antigravity is the third seat.** Reverses M0 AC-1. Preflight must assert `useG1Credits=false` in `~/.gemini/antigravity-cli/settings.json` before dispatch. *Evidence: §1.2–1.5.*

**AC-15 — Council provider homes are `CODEX_HOME` and `CLAUDE_CONFIG_DIR`, authenticated separately and once.** Preflight must detect the unauthenticated state and surface the exact login command rather than retrying. *Evidence: §2.1–2.3, §2.5.*

**AC-16 — A second isolation lever is needed for `~/.agents/skills`.** `CODEX_HOME` alone is insufficient. *Evidence: §2.1.*

**AC-17 — Treat 401 / not-logged-in as terminal.** No retries. Codex currently burns ~40 s across 10 attempts. *Evidence: §2.1.*

**AC-18 — Never pass `--settings` without an explicit `model` key,** and always verify the served model against the requested one. *Evidence: §2.4.*

**AC-19 — Build the single repair turn** for Antigravity, targeting the `structured_output`-absent failure. Justified by the pre-committed 80–94% band at 85%. Do not generalise to the other seats until they are measured. *Evidence: §3.1.*

**AC-20 — Per-turn timeout floor of 120 s**, not 60 s. *Evidence: §3.2.*
