# Documentation

## Purpose

Own durable Council architecture, security, acceptance, and operating documentation.

## Ownership

- architecture/ owns implementation plans and stable system contracts.
- security/ owns boundary and threat documentation.
- adr/ owns concise architectural decisions.
- evidence/ owns reproducible verification artifacts and evidence indexes.

## Local Contracts

- Document stable behavior, not a session diary.
- State unverified, blocked, and intentionally deferred work explicitly.
- Do not place secrets, raw credentials, or provider tokens in documentation.
- Keep the no-autonomous-implementation boundary visible in product and security docs.

## Verification

- Links and paths must point to current repository artifacts.
- Reports must identify the exact command and environment used for claims.
